## Формула

После подстановки констант из `docs/formula.txt`:

```text
full_training_cost(P) = 155.881361644759 × P² USD
```

где `P` — количество параметров в миллиардах.

Для fine-tune и adapter:

```text
fine_tune_cost(P) = full_training_cost(P) × F
```

Основной сценарий использует `F = 0.05`; чувствительность показана для `F = 0.01`
и `F = 0.10`. Это сценарное допущение, а не измеренная стоимость каждого запуска.

Для ориентира полное обучение по этой формуле стоит:

- 64B: $638 490;
- 128B: $2 553 960.

## Методика

- TAM: скользящие 12 месяцев, с 2025-08-12 по 2026-08-12.
- SAM: скользящие 24 месяца, с 2024-08-12 по 2026-08-12, effective parameter
  count от 64B до 128B включительно.
- Источник: публичный snapshot `cfahlgren1/hub-stats` (2 984 779 моделей) и
  `librarian-bots/model_cards_with_metadata`.
- Учитываются репозитории с распознанным файлом весов.
- Fine-tune/adapter определяется по `baseModels.relation`, PEFT/LoRA-тегам и
  устойчивым признакам в имени репозитория.
- Для adapter размер берётся у заявленной базовой модели; для full fine-tune — у
  опубликованных полных весов.
- Scratch включается только при явном ненегированном заявлении в карточке об
  обучении с нуля или random initialization.
- Scratch-зеркала с одинаковыми model card и parameter count дедуплицируются.
- Quantization, GGUF/GPTQ/AWQ/EXL2, merge, `compressed-tensors`, 4-bit и 8-bit
  публикации исключаются: это публикация/преобразование весов, а не обучение.
- Значения свыше 2T параметров исключаются как неподтверждённые выбросы. Этот cap
  не влияет на SAM 64–128B.

## Ограничения интерпретации

1. Репозиторий Hugging Face — proxy для проекта обучения. Один training run может
   породить несколько checkpoint-репозиториев, а один репозиторий может объединять
   несколько запусков.
2. Не все авторы заполняют `base_model` и model card. Консервативный фильтр снижает
   false positives, но пропускает часть реально обученных моделей.
3. Формула моделирует compute для dense pretraining по Chinchilla-подобному правилу
   20 токенов на параметр. Для MoE total parameters завышают active compute.
4. Fine-tuning существенно различается по числу токенов, эпох, sequence length и
   методу PEFT. Поэтому 1–10% следует показывать как сценарный диапазон.
5. Это оценка вычислительных затрат проектов, а не автоматически доступная выручка
   платформы. Для revenue TAM/SAM нужен дополнительный capture/take-rate.
